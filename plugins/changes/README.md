# changes

The Changes tab of the sidebar, in the `sidebar.panel` slot (contribution `changes/panel`, titled "Changes", with the number of uncommitted changes, then of committed ones when there are some, after its name through the `badge` option). One host `ChangeList` with two groups: Uncommitted, the working folder's changes against HEAD, untracked files included, through `useChanges(sessionId, "working")`; and Committed, what the commits of the session's branch changed since it left `origin/<default branch>`, through `useChanges(sessionId, "committed")`. The host lists both again after each change on disk. It follows the session on screen.

Each change is a row of the `ChangeList` (`src/rules/change-items.ts`). A click or Enter opens its diff beside the chat with `useOpenDiff` (kind `"committed"` in Committed), and the row of the diff on screen (`useDiffOnScreen`, which gives its path and kind) is selected. An uncommitted row's Discard button or the `changes.discard` command (⌫ on the focused row), and the Uncommitted heading's Discard all button or `changes.discardAll` (⌘⌫), both in the list's `changes` keybinding area, ask in a `Dialog` (`src/rules/discard-text.ts`), then run `useDiscardChanges` with the paths the dialog listed; a failure shows under the row or the heading. The group names both commands (`discardCommand`, `discardAll.command`), so the `ChangeList` shows their keys in the buttons' tooltips and gives them to screen readers.

States: no session on screen, no `origin` remote, no default branch on record, or no commit shared with it (Committed only), a deleted working folder, a working folder outside a git repository, no changes, and a listing git fails (the host's message, git's output under it, and Retry). The command `changes.show` (⌘3) opens the tab.
