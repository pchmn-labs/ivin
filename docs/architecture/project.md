# Project

What the design adds to the [glossary](../../GLOSSARY.md)'s terms in the `project` module, on the server and in the UI. The design shared by every module is in [the architecture](README.md).

- The open projects, their order, the selected project, the tabs, their order and each project's selected tab are stored in SQLite and restored at launch.
- Trust is stored per folder, by its real path, in SQLite beside the projects; the projects saved before trust existed were trusted by the migration that added it. `project.open` fails with `ProjectNotTrusted` unless the folder is inside a trusted project, or the call carries `trust`, which stores the trust first; the UI answers that failure with the trust dialog and calls again with `trust`. Whether a folder is inside a trusted project (`ProjectTrust`) is read from the files alone, with no git command: the folder is inside a trusted project's folder, or it is a worktree made outside ivin whose `.git` file points at a repository whose checkout is, and that repository's record of the worktree points back at it. The server checks it before every git command (in the `Git` adapter), where a refusal is a `GitError`, and before a message starts a session's agent, where `session.sendMessage` fails with `ProjectNotTrusted` and stores nothing in the transcript. A project opened from a `.code-workspace` file is stored with the file's path, and its folders (absolute, in the file's order, a duplicate or a folder given as a `uri` left out) are read from the file each time the projects are listed, so a folder added to the file appears at once. `project.open` checks the trust of every folder: when some are not trusted, `ProjectNotTrusted` lists them in `folders`, and the call with `trust` stores the trust of each; a file that cannot be read or lists no folder fails with `WorkspaceUnreadable`. Nothing is stored and no git command runs before that. For a session of a workspace that is not in its working folder of worktrees, the server checks that every project folder is trusted, since the session's folder may be none of them. `ProjectTrust` also accepts a working folder of a workspace session (`<~/.ivin/worktrees>/<workspace name>/<branch>`, or a folder in it) when one of its subfolders is a worktree of a trusted repository, with the same proof of the `.git` file as for a worktree made outside ivin. See [ADR-0010](../adr/0010-ivin-asks-the-user-to-trust-a-project-folder-before-running-git-or-an-agent-in-it.md).
