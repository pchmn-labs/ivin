# Worktree

What the design adds to the [glossary](../../GLOSSARY.md)'s terms in the `worktree` module, on the server and in the UI. The design shared by every module is in [the architecture](README.md).

- A workspace's session gets its working folder (`createWorkspaceWorkingFolder`) instead of one worktree: `~/.ivin/worktrees/<workspace name>/<branch with / replaced by ->` holds a worktree per project folder that is a git repository, in a subfolder named after the project folder (`-2`, `-3` when names collide), all on `ivin/<first 8 characters of the session id>` (`-2`… when any repository has that branch or the folder exists), each from its repository's fresh default branch. Every base is found before the first worktree is made; when one creation fails, the worktrees made and the folder are removed and the message is not sent. The working folder is not a repository, so `worktree.list` and `worktree.listBranches` are asked per project folder; the branch picker, the picking of a worktree and the cleanup of merged worktrees do not handle a workspace's working folder yet, and the cleanup skips a workspace.
- Worktrees are never stored: the server reads them from `git worktree list --porcelain`. Every git operation goes through the server's `Git` port (`modules/worktree/usecases/git.ts`), whose adapter runs the `git` binary; the decisions (branch name, worktree path, base branch, fetch reuse, what a picked branch resolves to) are pure rules fed with git's answers.
- The branch picker lists the project's local branches, each with the checkout or worktree that holds it, and `origin`'s branches as `origin/<name>`: first from the refs as they are, then again after a fetch of `origin` (skipped when the last attempt, failed or not, is younger than a minute; one fetch per repository runs at a time). Picking a branch resolves, from git's answers at that moment, to a checkout in the session's working folder, a tracking checkout of a remote branch with no local branch of its name, or a move to the worktree (or the checkout) that already holds it, since git refuses to check that branch out twice. A name that is not among the listed branches is refused before git runs, as a refused checkout. A pick is refused while the session runs a turn. After a move, the next message resumes the conversation in the new folder, as after an adoption. Each change appends a `working_folder` event with the cause `branch_picker`; a checkout git refuses changes nothing and returns git's message.
- When tabs close (`tab.close`, or `project.close` for all of its tabs), and once their agents are stopped, the server removes the project's merged worktrees in the background, when `worktrees.removeOnTabClose` is on; two removals never run at the same time. After a fresh fetch of `origin`, it removes (`git worktree remove`, which keeps the branch) each worktree of a session whose tab closed, and each worktree under `<project>/.worktrees/` with commits of its own, when the worktree is on a branch, no session with an open tab or a running agent is in it (checked again just before the removal), it has no local or untracked changes, and its branch is merged into `origin/<default branch>`. Merged means that merging the branch (`git merge-tree`) leaves the default branch's tree unchanged, or that one commit of the default branch has the branch's whole diff (`git patch-id`), as a squash merge does. The checkout is never removed. Sessions in a removed worktree are then marked as having a deleted working folder.
- Every git command is stopped after its time limit and fails with a `GitError` that names it: 10 minutes for a command that writes the working tree (checkout, `worktree add`, stash, commit, merge, restore), whose smudge filters, such as Git LFS's, can take minutes, and 30 seconds for every other command. A fetch gets 10 minutes too, as the origin fetch stops it after 30 seconds with an error of its own.
- Every git command runs in a folder inside a trusted project, or is refused before git starts ([project](project.md)). It runs with `core.fsmonitor=false`; a read (status, diff, log, rev-parse, ls-files, merge-base, patch-id…) also with `core.hooksPath=/dev/null`, a fetch with `protocol.ext.allow=never`, and every diff with `--no-ext-diff --no-textconv`. Clean and smudge filters, the hooks of a commit, a checkout or a merge, and the fetch's credential and SSH settings still apply: Git LFS and a user's own setup rely on them. See [ADR-0010](../adr/0010-ivin-asks-the-user-to-trust-a-project-folder-before-running-git-or-an-agent-in-it.md).
- A git failure is never an empty result. Outside a git repository the listing of worktrees and of branches is empty; inside one, a failure (a time limit included) fails `worktree.list` and `worktree.listBranches` with `WorktreeGitFailed`, which carries git's output. The working folder picker and "Where should the agent continue?" show a message with Retry in place of the existing worktrees, and the branch picker shows its message with git's output, as for a refused checkout. Removing merged worktrees treats a failed listing as nothing to remove, and logs it.
- A stash made before a switch or a pull that git then refuses is put back when HEAD has not moved (`git stash pop`); when HEAD has moved, or the pop fails, the message names the stash that holds the changes.
