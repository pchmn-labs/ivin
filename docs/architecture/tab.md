# Tab

What the design adds to the [glossary](../../GLOSSARY.md)'s terms in the `tab` module, on the server and in the UI. The design shared by every module is in [the architecture](README.md).

- A tab stores its project and its position, so a single bar for all projects can later be a view over the same rows.
- `tab.open` takes an optional `after`, the session whose tab the new one follows; a session that already has a tab keeps its place. The UI sends it for `tab.new` and the tab bar's + button when `tabs.newTabPosition` is `afterCurrent`.
- A tab stores its sub-views in SQLite, in order (a sub-view is a [view](../../GLOSSARY.md) opened in the tab's row: its name `<plugin id>/<view>` and its `params`, a JSON object, printed with sorted keys so equal params are one identity), with the selected one and the working folder each was opened in (`tab.listSubViews`, `tab.openSubView`, `tab.closeSubView`). The tab's row stores whether it is in full width and whether its Session tab is selected (`tab.setFullWidth`, `tab.selectSessionTab`); opening a sub-view or going back beside the chat leaves the Session tab. Listing, opening or closing first drops those of another working folder than the session's, whatever moved the session; closing the tab or deleting the session drops them all. The UI keys them by session and working folder, so a moved session loads them again.
- When the server starts it drops the stored sub-views whose view declares `restore: false` in its manifest (`tab/usecases/drop-unrestored-sub-views.ts`); a selected one that goes leaves the last remaining one selected. Migration 25 turned the stored `file`, `diff` and `committed_diff` rows into `files/file` and `changes/diff` (`{ path }`, `{ kind: "working" | "committed", path }`).
- Views in the sheet and in a dialog are never stored: the UI keeps them per session and working folder (`view/atoms/overlay-views.ts`), so they close when the session moves, and the sheet's tab per view and the dialog (one at a time, a new view replacing it) come from them. Where a view opens is decided in the UI (`view/rules/placement.ts`, `view/atoms/open-view.ts`): the setting `<plugin id>.<view>.placement`, then the caller's, then the manifest's default. An equal view that is open in any placement is selected where it is.
- An open view moves to another of its placements from its frame's "Move to" menu: the right-click menu of its tab beside the chat or in the sheet, or the dialog's title. `view/atoms/move-view.ts` closes it where it is (through `tab.closeSubView` for a sub-view) and opens it in the other placement with the same params; the setting decides only where a view opens. The command `view.moveTo` (⇧⌘O) opens that menu for the view whose frame holds the focus, else the dialog's, the sheet's, then the selected sub-view's; after a move the focus goes to the view's tab, or into the dialog.
- Closing a tab, or the project it belongs to, ends its session's agent process when `tabs.stopAgentOnClose` is on; the next message starts a new process that resumes the conversation. The tab bar asks first when the agent is working or waiting; closing a project does not ask.
